# KREW — контрольный список до публичного запуска

Этот кандидат проверен локальными тестами. **Не считай его прошедшим боевую проверку, пока не выполнены шаги ниже.**

- [ ] Перевыпустить и безопасно сохранить токен в `.env` (никогда не отправлять его в чаты и репозитории).
- [ ] Остановить старый KREW, сохранить резервную копию через `python backup.py`, перенести данные через `python upgrade.py ...`.
- [ ] Запустить `python release_check.py` и `python -m unittest discover -s tests -v`.
- [ ] Проверить `/diagnostics`: бот — администратор группы, разрешены удаление сообщений и ограничение участников.
- [ ] Выставить постоянный HTTPS через доверенный reverse proxy; порт HTTP не должен быть напрямую открыт наружу.
- [ ] Проверить Mini App с настоящей авторизацией Telegram, без `?preview=1`.
- [ ] Участник запускает ЛС с ботом (`/start`), жалуется в группе, администратор отклоняет жалобу с причиной через Mini App.
- [ ] Проверить фактическую доставку ЛС и `/myreports`, затем отключение `/notify off`.
- [ ] Проверить жалобы через администраторские кнопки и ответ с причиной в личке.
- [ ] Убедиться, что чужой пользователь не может получить доступ к настройкам и решениям.
- [ ] Проверить предупреждения, автоматический мут, фильтры, капчу, анти-рейд в **отдельной тестовой группе**, а не сразу в публичном чате.
- [ ] Проверить 429/retry_after, нестабильный интернет, закрытие программы, повторный запуск и отсутствие двух одновременно работающих процессов.
- [ ] Провести тест нагрузки на базе ожидаемого числа чатов, настроить мониторинг и автоматический рестарт.
- [ ] Проверить резервные копии **восстановлением** на другой копии проекта. Настроить ежедневное резервное копирование.
- [ ] Опубликовать правила и политику обработки данных: ID, игровая активность, причины решений по жалобам; срок хранения журналов и жалоб — 30 дней.
- [ ] Получить обратную связь от первых администраторов и устранить найденные ошибки до публичного релиза.

**Ограничения:** Telegram запрещает боту начинать личный диалог первым. Уведомление придёт только после `/start`, если сообщения не отключены и пользователь не заблокировал бота. История сохраняется в `/myreports`, пока запись не удалена по сроку хранения. Сервис использует SQLite и один процесс; многосерверная нагрузка пока не поддерживается. Монетизация, биллинг Stars и распределённые очереди отсутствуют.
