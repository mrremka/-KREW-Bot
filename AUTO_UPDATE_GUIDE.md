# KREW: GitHub Releases, автообновление и новости в личке

## 1. GitHub (один раз)

1. Подключи GitHub к ChatGPT, если хочешь, чтобы в следующих разговорах я мог помогать публиковать изменения в разрешённых репозиториях. Подключение само по себе **не означает** постоянного автономного доступа или автоматического написания обновлений.
2. Создай **публичный** GitHub-репозиторий с исходным кодом KREW из папки проекта; НЕ добавляй `.env`, базу `data/`, логи и бэкапы.
3. Сначала загрузи в основную ветку **все** файлы, включая `.github/workflows/release.yml` и `scripts/`.
4. Разреши GitHub Actions запись в репозиторий: Settings → Actions → General → Workflow permissions → Read and write permissions (если необходимо). При защите default branch может требоваться другой способ записи manifest.
5. На сервере или ПК впиши в `.env` официальный адрес манифеста, подставив свой `OWNER/REPO` и имя основной ветки (обычно main):

```env
AUTO_UPDATE=1
UPDATE_CHANNEL=beta
UPDATE_MANIFEST_URL=https://raw.githubusercontent.com/OWNER/REPO/main/updates/beta.json
UPDATE_CHECK_INTERVAL=3600
ANNOUNCE_UPDATES=1
```

Для стабильного канала используй `stable.json` и `UPDATE_CHANNEL=stable`. Боту потребуются права чтения HTTPS URL, GitHub-токен для самих обновлений не нужен.

**Запускай `python launcher.py` вместо `python main.py`.** Именно launcher проверяет новые версии, резервирует БД, аккуратно останавливает процесс, заменяет файлы и перезапускает бот. Обновлятор проверяет SHA-256 и домены URL. Релизы должны поступать только из **твоего** репозитория: владелец манифеста контролирует исполняемый Python-код. Не подключай чужие источники обновлений.

Проверка вручную: `python updater.py version`, `python updater.py check`. Откат кода после неудачного запуска предусмотрен, а БД автоматически не откатывается, чтобы не уничтожить новые сообщения/настройки. Отдельная резервная копия БД хранится в `.krew_updates/backups/`.

## 2. Публикация версии на GitHub

1. Обнови `VERSION` (например, `1.0.0-rc.3`) и `release_notes.json` с той же версией, названием и изменениями.
2. Отправь изменения в основную ветку (лучше через pull request и тесты).
3. Создай и отправь точный тег версии `v1.0.0-rc.3`.
4. GitHub Actions протестирует проект, соберёт ZIP, опубликует GitHub Release и обновит `updates/beta.json` (stable для версии без `-rc.*`). Новые установленные боты обнаружат манифест во время очередной проверки.

**Не пересоздавай теги** и не подменяй архив уже опубликованной версии. Код GitHub Actions проверяет тег, VERSION и заметки релиза; при провале тестов публикация не выполняется. GitHub Actions должен иметь `contents:write` и право обновлять ветку.

## 3. Личные уведомления о новых версиях

Участник открывает бота **сам** и отправляет `/start`, затем `/news on`. Команда `/news off` отключает релизные уведомления в любой момент. Это отдельная подписка от `/notify on/off`, которая управляет уведомлениями о жалобах.

При первом запуске конкретной новой версии, если `ANNOUNCE_UPDATES=1`, KREW создаёт очередь **только для уже подписанных пользователей**. Отправляет в ЛС заголовок и пункты из `release_notes.json`, сохраняет статус каждого получателя в SQLite. Повторный запуск не создаёт дублей. Telegram может не доставить сообщение, если пользователь заблокировал бота; бот это учитывает. Ограничение частоты: рассылка отправляет не более одного сообщения за короткий цикл, при Telegram 429 повторяет после `retry_after`.

**Не включай массовые личные сообщения без согласия пользователей.** Telegram-бот не может сам начать разговор с человеком, который не отправил `/start`.

## 4. Реальное ограничение

ChatGPT без подключённого GitHub не может отправить в твой аккаунт код и самостоятельно работать вне разговора. После подключения я могу помогать создавать коммиты, PR и релизы в рамках разрешённых операций; публикация на тегах, проверка серверных обновлений и рассылка после деплоя выполняются GitHub Actions и работающим KREW. ChatGPT не должен хранить твой GitHub-токен или BOT_TOKEN в тексте диалога.

## 5. Docker

Не стоит использовать встроенный updater для неизменяемого Docker-образа. Для Docker: после публикации тега собирай и разворачивай новый образ через CI/CD; KREW запустится и сформирует очередь новостей. Сохраняй volume базы данных. На Windows или обычном Linux-процессе используй `python launcher.py` и не запускай одновременно `main.py`.
