# KREW 1.0.0-rc.1 — Release Candidate

Все функции версий 0.1–0.6 сохранены. Изменения аддитивны по отношению к базе 0.6.

## Жалобы и уведомления
- Отклонение жалобы **только с причиной** длиной 5–300 символов (Mini App и личный ответ модератора в боте).
- Кнопка «Отклонить с причиной» в администраторском диалоге. Она выдаёт запрос `ForceReply` с привязкой к жалобе.
- Решение, причина, ID администратора, время рассмотрения и статус отправки ЛС сохраняются в SQLite.
- При подтверждении нарушения — отдельное приватное предупреждение нарушителю без раскрытия личности заявителя, также только после `/start`.
- Автоматическое ЛС заявителю, только если ранее было `/start`, уведомления включены и бот не заблокирован.
- `/myreports` — личная история поданных обращений, `/notify on|off` — настройки уведомлений.
- Новая история решений в Mini App, включая причины отклонения и статус личного уведомления.
- Прежнее действие `close` сохранено для совместимости со старыми кнопками; оно теперь записывает фиксированную причину, и пользователь тоже может получить уведомление.
- Дублирующиеся решения блокируются атомарным `UPDATE WHERE status='open'`.
- Проверка прав администратора в момент решения, повторная проверка, что обвиняемый не является администратором, при предупреждении.

## Эксплуатация
- `release_check.py` — локальный предрелизный аудит конфигурации и базы.
- Dockerfile, compose.yaml для контейнеризации, `.dockerignore` без секретов.
- Улучшен раздел «Жалобы» в Mini App с обязательной формой причины и историей решений.

## Ограничения
- До успешных **живых** тестов с настоящим Telegram, HTTPS, восстановления бэкапов и нагрузки это кандидат на релиз, а не готовый публичный SaaS.
- SQLite рассчитана на один экземпляр работающего бота.
- Коммерческие подписки и платёжная система не реализованы.

## 1.0.0-rc.2 — GitHub publishing + opt-in news

- Проверяемые обновления, `updater.py`, управляющий процесс `launcher.py`, журнал отката и резервная копия базы.
- Публикация архивов GitHub Releases и каналов `beta/stable` через GitHub Actions после успешных тестов.
- Команды `/news on` и `/news off` в личке, независимые от уведомлений о жалобах.
- Однократная очередь новостей для уже подписанных пользователей, Telegram retry-after и отказ от дублирования неясных отправок.
- Заметки релиза в `release_notes.json` для GitHub Releases и уведомлений.
- **До подключения репозитория** никаких самостоятельных публикаций и обновлений не происходит. Рассылки по умолчанию выключены.

## 1.0.0-rc.3 — GitHub-first publishing

- Импорт полного исходного кода в официальный репозиторий KREW.
- Автоматический запуск CI на изменениях в main и pull request.
- Публикация проверенного GitHub Release автоматически после обновления VERSION и release_notes.json.
- Исправлена привязка теста заметок релиза к номеру версии; уведомления в ЛС остаются добровольными.

## Репозиторий и обновления

- Убраны пользовательские инструкции по установке и запуску из репозитория; инструкции теперь предоставляются в личном диалоге.
- В GitHub остаются исходники, история изменений, метаданные релизов и техническая автоматизация.

## 1.0.0-rc.4 — проверка запуска и инструменты администратора

- Добавлены команды `/version` и `/status` для проверки установленной версии, доступности бота и Mini App.
- Администраторам доступны `/pin` и `/unpin`; все действия проверяют роль и фиксируются в журнале.
- Справка обновлена, сообщение об ошибке прав стало точнее; старые данные не затрагиваются.
- Добавлены 8 автоматических тестов для новых команд.

## 1.0.0-rc.5 — проверка автоматического обновления

- Команда `/ping` в личном чате отвечает номером установленной версии, чтобы быстро проверить запуск нового кода после обновления.
- Добавлены 3 теста новой команды; сохранены функции и данные предыдущих релизов.
- ZIP-архив публикуется через GitHub Actions и доставляется по beta-манифесту с проверкой контрольной суммы.

## 1.0.0-rc.6 — защита приватных параметров панели

- В журнале HTTP-сервера не сохраняются URL, query-параметры и произвольные клиентские строки, которые могут содержать подписанные Telegram-данные.
- В логах остаются только HTTP-метод и код ответа.
- Добавлено четыре теста приватности логов и проверки /health.
- Настройки групп, база данных и система обновлений не затронуты.

## 1.0.0-rc.7 — интерфейс команд и компактные таблицы

- Интерактивный /help с шестью разделами и редактированием одного сообщения.
- Статистика группы, статус и профиль получили таблицы Telegram Rich Messages с обычным HTML-форматом на случай несовместимости.
- Единый спокойный стиль сообщений и рассылок обновлений.
- Проверки прав модерации, структура данных, Cloudflare и автообновление сохранены.
